# Astra Effort Fit — Pro

GPT-6 Astraを選択した場合だけ、GPT-5.6 Luna / low がエフォートだけを審査するCodexプラグインです。
Astra以外のモデルは審査せず、そのまま通常実行します。実行モデルは変更しません。
先頭の `/claude:review`・`$agy:ask`・`$grok:review` 等の既知の呼び出しコマンドと、
`[$claude:review](.../SKILL.md)` 等のスキル選択リンクも審査対象外です。
本文中の言及・引用例・自然言語だけの依頼は対象外判定に使いません。
呼び出し後のCodex側の処理には、選択モデルの利用枠を使う場合があります。
通常のユーザー送信を同期Hookで停止し、明示承認した指示だけ実行へ進めます。

## この版の基準

Plus版固有の高effort抑制は行いません。推論難度に見合う最小十分なeffortを推奨し、過剰・不足の両方を指摘します。

Plus/Proの利用制限・料金・残時間を推定する機能ではありません。プラン名は審査方針の違いです。
審査でモデルの変更は提案しません。審査役は `gpt-5.6-luna` に固定し、利用不可でも上位モデルへ切り替えません。

## 必要環境と導入

- Codex CLI（検証版 0.153.4）、ChatGPTアカウントでの `codex login`、Lunaの利用権。
- Python 3.10以上（Windowsは `python`、macOS/Linuxは `python3` がPATHに必要）。
- Windowsのnpm版CodexはNode.jsもPATHに必要です。追加のPythonライブラリやAPIキーは不要です。
- Plus版・Pro版は**片方だけ**インストールして有効にしてください。同時に有効だと両方が審査・停止します。

Personalマーケットプレイス登録済みの環境ではCodexのプラグイン一覧で `astra-effort-fit-pro` を選んでインストールできます。
CLIでインストールする場合: `codex plugin add astra-effort-fit-pro@personal`。
ZIPはソース配布用です。別PCではCodexのローカルプラグイン登録手順に従ってください。

インストールだけではHookは信頼されません。CLIの `/hooks`（またはアプリのHookレビュー画面）で
このプラグインのUserPromptSubmit Hookを確認し、信頼して有効化してください。
**信頼を自動登録する処理や、グローバル設定の書き換えは含めていません。**
新しいタスクを開始し、最初は「テストです。何も変更せずOKと答えて」のような指示を送ってください。
Lunaの判定と承認コードが表示され、実行モデルの回答が出ないことを確かめてから通常利用してください。

## 使い方

1. 実行モデルとeffortを選び、通常どおり指示を送ります。適正なeffortでも毎回停止します。
2. Lunaの判定で「現在」「推奨」「過剰/適正/不足」「理由」が表示されます。
3. 採用するeffortをCodex画面で選びます。推奨と別の値を選ぶこともできます。
4. 推奨値を採用する場合は、**同じメッセージをそのまま再送**します。その再送を承認とし、再審査せず実行します。
   最初から推奨値と同じ場合も、判定を確認してからもう一度送信してください。

推奨と異なるeffortを採用する場合だけ、以下の形式で承認コードと採用effort、その下に元の指示全文を送ります。

```text
effort-fit approve <表示された承認コード> medium
元の指示全文を変更せずに貼り付ける
```

承認は30分以内・同じタスク/作業場所/モデル/指示本文で1回限りです。
採用effortと現在ターンの実設定が一致しなければ停止します。
承認時にLunaは再呼び出ししません。新しい指示は新たな審査になります。
取り消すには `effort-fit cancel` のみを送ります。
保留データが破損・旧形式の場合も、この取消操作の後に元の指示を再送すると再審査できます。
`effort-fit approve の使い方を教えて` などの通常質問は審査対象です。
承認コマンドの書式と区別できない質問は、先頭に「質問: 」を付けてください。
指示本文が変わった場合や30分の期限が切れた場合は、新しく審査します。以前のコードは無効になります。
同じ本文を推奨値と違うeffortで再送した場合は、前回の推奨を案内し、Lunaの再審査は行いません。

## 判定と実行の範囲

- Lunaには指示本文・現在effort・Plus/Pro方針だけを渡します。会話全体や作業ファイルは渡しません。
- 原因や対象ファイルがまだ不明な通常の調査・修正も、エフォートを見積もって承認へ進めます。
- 「それを直して」など前の会話だけで意味が決まる指示は判断材料が限られます。
  その場合はmediumの暫定推奨と承認コードを表示します。詳細確認は承認後に行います。本文上限は24,000文字です。
- Lunaはread-onlyの一時CLIで動作します。シェルツール・Web検索・プラグイン・Hook・ユーザー設定読込を無効にし、指示でもツール使用を禁止します。
- 審査にもCodex利用枠を使います。90秒で打ち切り、自動再試行しません。
- Hookはeffortを変更できないため、画面操作が必要です。グローバルconfigの値からは推測しません。
- 現在effortはHookの `transcript_path` の最新4MiBにある、**同じturn_idとmodel**の
  `turn_context.effort` から検証します。記録形式は非安定APIです。取得不能なら停止します。
- ephemeralセッションなど記録がない実行には対応しません。
- 審査の失敗・不正な出力・設定不明・承認不一致は実行を止めます。

## 保証の境界と復旧

CodexがHookを起動し、同期で結果を扱うことが前提です。未信頼・無効化・Python不在・
Hookプロセス自体の起動失敗/外側のタイムアウトでは、Codex側が処理を続ける可能性があります。
このプラグインはアプリ本体を改変せず、すべての経路の絶対的な強制は保証しません。
送信前に別のHookがモデルを呼び出す場合、その消費は防げません。
既に実行中のターン、実行中への追加指示、内部継続、サブエージェントなどは通常の新規送信と
同じ停止保証がないため、**停止中のタスクに通常送信する運用**で使ってください。

保留データ（指示本文を含む）はCodexの `PLUGIN_DATA` 配下にローカル保存します。
環境変数がない直接実行時は `~/.codex/effort-fit/pro` を使用します。
承認・取消で保留ファイルを削除します。未承認データは次の指示で置換され、期限後も再送/取消までは残ります。
同じタスクの重複送信はロックで停止します。異常終了後の `.lock` ディレクトリは、
審査プロセスが終了していることを確認してから対象タスク分だけ削除すると復旧します。
Codex更新後は動作確認を再実施してください。
